# S02 — Day notes to DB

## Built
- New `DayNote` model (`date` is a unique Postgres `DATE`, `text`, timestamps). Migration `add_day_note_table` only adds a table.
- Server actions in `app/meal-plan/dayNoteActions.ts`: `getDayNotesForWeek(weekStart)` and `saveDayNote(date, text)` (empty/whitespace text deletes the row).
- `useDayNotes(startDate, days)` now loads/saves through those actions. Component API is unchanged (`dayNotes` keyed by day name, `handleNoteChange(day, text)`); saves are debounced 600ms per day. Past weeks are no longer cleared.
- One-off localStorage migration in `lib/hooks/migrateLocalStorageNotes.ts`.
- Tests: action unit tests, hook unit tests (load, history, debounce, migration), and a real-Postgres integration test of the date round-trip.

## Decisions
- Dates cross the server boundary as `YYYY-MM-DD` strings and are stored at UTC midnight in a `DATE` column, so there is no timezone shift. `formatDateParam` produces the strings on the client.
- Last write wins if two devices edit the same day; no merge logic.
- Migration only moves notes for current/future weeks (per prompt). Past-week keys are left in localStorage untouched.
- Removed four `useMealPlan.test.ts` tests that asserted localStorage persistence / past-week clearing (behaviour that no longer exists); the equivalent coverage is in `useDayNotes.test.ts`.
- Branch is named `claude/bold-franklin-mpgtde` on the remote (harness requirement) rather than `rehaul_S02_day_notes_db`.

## Handoff
- S12 can read history with `prisma.dayNote.findMany({ where: { date: { gte, lte } } })`; `date` comes back as a UTC-midnight `Date`, format with `toISOString().split('T')[0]`.
- Notes are not yet linked to a `MealPlan` row; they are keyed by calendar date only.
- **`lib/hooks/migrateLocalStorageNotes.ts` can be deleted** (plus its import/call in `useDayNotes.ts` and its test) once both devices have loaded the app after deploy — about 2–3 weeks after merge.
- No save-error UI: a failed save is only logged to the console.
