# S02 — Day notes to DB

## Built
- New `DayNote` model (`date` is a unique Postgres `DATE`, `text`, timestamps). Migration `add_day_note_table` only adds a table.
- Server actions in `app/meal-plan/dayNoteActions.ts`: `getDayNotesForWeek(weekStart)` and `saveDayNote(date, text)` (empty/whitespace text deletes the row).
- `useDayNotes(startDate, days)` now loads/saves through those actions. Component API is unchanged (`dayNotes` keyed by day name, `handleNoteChange(day, text)`); saves are debounced 600ms per day. Past weeks are no longer cleared.
- One-off localStorage migration in `lib/hooks/migrateLocalStorageNotes.ts`.
- Tests: action unit tests, hook unit tests (load, history, debounce, migration), and a real-Postgres integration test of the date round-trip.

## Decisions
- Dates cross the server boundary as `YYYY-MM-DD` strings and are stored at UTC midnight in a `DATE` column, so there is no timezone shift. `formatDateParam` produces the strings on the client.
- Last write wins if two devices edit the same day; no merge logic.
- Migration only moves notes for current/future weeks (per prompt). Past-week keys are left in localStorage untouched.
- Removed four `useMealPlan.test.ts` tests that asserted localStorage persistence / past-week clearing (behaviour that no longer exists); the equivalent coverage is in `useDayNotes.test.ts`.
- Built on the earlier S02 commit (cherry-picked), then reviewed and fixed gaps: (1) typing then navigating/reloading within the 600ms debounce lost the note, so pending saves are now flushed on unmount, tab hide and pagehide; (2) the old localStorage key date came from `toISOString()` (UTC), so east of UTC (UK summer time) the key is the day BEFORE the real Monday and the migration would have shifted notes a day. The migration now resolves the real week start as the key date or the next day, whichever is the week-start day; (3) the migration no longer overwrites a note already in the DB; (4) the hook clears the previous week's notes while a new week loads, and does not clobber text typed before the load finished; (5) the server action rejects impossible dates such as 2026-02-31.
- Save failure message: a `sonner` toast ("Could not save your note. Check your connection and try again."), the same mechanism the page already uses for generate errors; one toast id so it does not stack. No inline UI added.
- No new migration was needed beyond `add_day_note_table` (additive only); `prisma migrate dev` reports no drift.

## How it works
Design: the browser used to keep notes in its own storage, so each device had its own. Now there is a `DayNote` table (one row per calendar date, `date` is a Postgres DATE so no time or timezone is stored). Migration `add_day_note_table` only creates that table and a unique index on date.

The hook `useDayNotes` still hands the grid `dayNotes` keyed by day name and `handleNoteChange(day, text)`. Inside, `dateForDay` turns "Thursday" into `YYYY-MM-DD` using `formatDateParam` (local calendar day). Loading calls the server action `getDayNotesForWeek(weekStart)`; typing updates state at once and `saveDayNote(date, text)` is sent after 600ms of quiet (or immediately on leaving). Empty text deletes the row. Dates travel as plain strings and are stored at UTC midnight, so the server timezone never shifts a day.

The one-off migration (`migrateLocalStorageNotes`) runs before the first load: finds `mealPlanNotes_*` keys for current/future weeks, pushes missing notes to the DB, removes the key.

## Try on the preview
- Open Meal Plan, type a note on a day, wait a second, open the same page on another device: the note is there.
- Type a note and straight away tap Next Week then Previous Week: the note is still there.
- Go to a past week you used before: its notes are still shown.
- Clear a note's text, reload: it stays empty.
- Turn on airplane mode and type a note: a red "Could not save your note" toast appears.

## Tried in the running app
next dev against local Postgres, driven by Playwright (Chromium): typed a note, reloaded, navigated forward/back, quick navigate after typing, past-week note kept, empty text deleted, legacy localStorage migration (UTC-style key) landed on the right day and the key was removed, blocked save request showed the toast, and browser timezones Pacific/Auckland and America/Los_Angeles showed the same dates and wrote the same DB date.

## Handoff
- S12 can read history with `prisma.dayNote.findMany({ where: { date: { gte, lte } } })`; `date` comes back as a UTC-midnight `Date`, format with `toISOString().split('T')[0]`.
- Notes are not yet linked to a `MealPlan` row; they are keyed by calendar date only.
- **`lib/hooks/migrateLocalStorageNotes.ts` can be deleted** (plus its import/call in `useDayNotes.ts` and its test) once both devices have loaded the app after deploy — about 2–3 weeks after merge.
- A failed save shows a toast and is not retried automatically; the next edit of that day saves again.
