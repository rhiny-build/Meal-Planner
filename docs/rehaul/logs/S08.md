# S08 — Cook mode

## Built
- On a recipe page, **Cook** is now a real button. It opens a full-screen cook view (`/recipes/[id]/cook`) with one step per screen: huge text, the step number ("Step 2 of 5") with a progress bar, and big Back / Ingredients / Next buttons along the bottom where a thumb reaches. The last step's Next becomes Finish and returns to the recipe page. Arrow keys work on a keyboard.
- **Ingredients** is one tap away: a sheet slides up with every ingredient at the chosen servings.
- **Servings** (minus / plus at the top) rescales the ingredient list and every amount written inline in the step text. Ingredients with a free-text quantity ("to taste") are shown as written, with a small "not scaled" mark in the list.
- **Timers**: a step with a timer shows a big clock with Start / Pause / Resume / Reset. Any number can run at once. A strip under the header lists every started timer ("Step 2 · 8:00"); tap one to jump to its step. When a timer ends, the strip chip turns red and pulses, the phone beeps and vibrates (where supported), even if you are on another step.
- The screen is kept awake while cooking where the browser supports it ("Screen stays on" is shown when the lock is held).
- **No method**: the ingredients plus a quiet "There's no method for this recipe yet." and a marked, invisible slot for S09. **Quick recipes** get a single scrolling screen (ingredients, then the method as a list with timers), no stepping.

## Decisions
- **One step per screen** (Ronen's decision, not revisited).
- **Full-screen overlay** (`fixed inset-0`) over the normal site header/footer, so there is nothing to mis-tap while cooking; a Close button returns to the recipe page.
- **Timers store an end time, not a counter**, so a throttled or sleeping tab still finishes on time; a tick runs 4x a second only while a timer is running. One timer per step (keyed by step id); starting a finished timer restarts it.
- **Alert** = four short beeps (Web Audio) plus a vibration pattern. Browsers only allow sound after a tap, so the audio context is unlocked when Start is pressed. Finished timers stay red in the strip until tapped. Vibration does nothing on iOS Safari (unsupported there); the beeps and the red pulsing chip still happen. No browser notifications or service worker: a locked phone will not alert, which is why the screen is kept awake.
- **Servings control hidden when the recipe has no servings count**; the header says "Amounts as written" and nothing scales. Amounts are never guessed.
- Servings range 1 to 99. Servings and step are not remembered between visits.
- **Quick recipes are one screen**, even if they have steps (timers still work); full recipes with steps are stepped.
- Legacy recipes with no structured ingredients show the old one-per-line text as unscaled lines, so cook mode is never empty.
- The `S09` slot is `components/cook/CookCaptureSlot.tsx`, an empty hidden element today.
- No Playwright package in the repo, so Playwright was run from a scratch folder against the pre-installed Chromium (`/opt/pw-browsers`), not committed. `npm run lint` is broken in the repo (`next lint` cannot find the project dir), so lint was not run; `tsc --noEmit` is clean.
- No schema changes, no AI.

## How it works
**Design.** The server page (`app/recipes/[id]/cook/page.tsx`) loads the recipe, its structured ingredients and steps, and passes plain data to one client component, `CookScreen`. `CookScreen` owns the three things that must survive changing step: the current step, the chosen servings, and the timers. Everything else is small presentational pieces (`CookStepView`, `StepTimer`, `ActiveTimersBar`, `IngredientsSheet`, `ServingsControl`, `CookNoMethod`, `CookQuickView`). The logic is in plain functions in `lib/cook/` so it is unit-tested without a browser.

**How scaling flows into the step text.** The servings control sets `servings` state. `CookScreen` computes one number, `scale = servings / recipe.servings` (`getServingsScale`), and passes it down. Step text is stored with tokens like `Brown {ing:abc123}`. `StepText` splits the text into words and ingredient tokens (S03's `parseStepText`), looks each ingredient up and prints `describeIngredient(ingredient, scale)`, which multiplies the ingredient's numeric `amount` by `scale`. The ingredient list and the sheet use the same call, so they always agree with the step text. An ingredient with no numeric `amount` ignores `scale` and shows its free-text quantity.

```ts
const scale = getServingsScale(servings, recipe.servings)   // 6 / 4 = 1.5
describeIngredient({ name: 'beef mince', amount: 500, unit: 'g' }, scale) // "750 g beef mince"
```

**How timers keep running when you change step.** The timers do not live in the step view; they live in the `useCookTimers` hook called once in `CookScreen`, which never unmounts while you move between steps. The state is a map `{ stepId: { status, endsAt, remainingMs } }`. Start sets `endsAt = now + remaining`; pause stores what is left; a 250 ms interval (only while something runs) calls `tickCookTimers(timers, Date.now())`, which flips timers whose `endsAt` has passed to `done` and reports them once, which fires the beeps and vibration. The step view just reads its own entry for the big clock; the strip reads all of them.

```ts
const { timers, finishedStepIds } = tickCookTimers(timersRef.current, Date.now())
```

## Try on the preview
1. Open a recipe that has a method (e.g. Beef Keema once it has steps), tap **Cook**. You should see one big step, "Step 1 of N", and Back / Ingredients / Next at the bottom.
2. Tap + twice next to servings. The amounts in the step text change (4 to 6 servings: 500 g becomes 750 g). Tap **Ingredients**: the sheet shows the same scaled amounts.
3. On a step with a timer tap **Start timer**, tap Next, start another timer on a later step. Both show in the strip under the header. Let one finish: it turns red, the phone beeps and vibrates (Android), even on a different step. Tap the chip to jump back.
4. Open a recipe with no method and tap Cook: ingredients plus "There's no method for this recipe yet." Open a quick recipe (e.g. Simple Fries): one scrolling screen.
5. Leave the phone alone for a minute while cooking: the screen should stay on ("Screen stays on" under the title).

## Handoff
- **Where S09's "tell me as you go" goes:** `components/cook/CookCaptureSlot.tsx`. It is rendered in `CookNoMethod` (full recipe, no method) and in `CookQuickView` when a quick recipe has no steps. Props contract (`CookCaptureSlotProps`): `{ recipe: CookRecipeData, servings: number }`. It currently renders a hidden `<div data-testid="cook-capture-slot">`. S09 replaces its body. If S09 wants the capture to be reachable from a full recipe that already has steps, that needs a new mount point in `CookScreen`.
- **Data shape** (`components/cook/cookTypes.ts`): `CookRecipeData { id, name, kind, servings: number | null, ingredients: CookIngredientData[], steps: { id, order, text, timerSeconds }[] }`. `CookScreen` takes `{ recipe }`; its state is local (`stepIndex`, `servings`, `isIngredientsOpen`) and the timers are in `useCookTimers`. There is no shared store, so S09 state should live in its own component or hook.
- After S09 saves a method, `router.refresh()` on the cook page re-reads steps from the server and the stepped view appears (the page is `force-dynamic`).
- Timer logic (`lib/cook/cookTimers.ts`), scaling (`lib/cook/scaleServings.ts`) and navigation (`lib/cook/stepNavigation.ts`) are pure and reusable.
- A free-text quantity renders as "to taste salt" via S03's `describeIngredient` (quantity, unit, name). Reads awkwardly for non-numeric text; see backlog below.
- Dev DB used: local `meal_s08`; Beef Keema, a no-method recipe and Simple Fries were inserted by a throwaway script (not committed), since the seed data has no Beef Keema.
