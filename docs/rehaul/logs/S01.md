# S01 — Claude swap

## Built
- All generative AI now runs on Claude: URL import, meal-plan modify, ingredient normalisation (master items and single recipe ingredients), and Inspire Me.
- Inspire Me no longer uses Perplexity. Claude searches the web itself (server-side web search) and returns the same 3-recipe shape, so `InspireModal` is unchanged apart from a comment.
- OpenAI is used only for embeddings (client renamed to `lib/ai/openaiEmbeddings.ts`, behaviour and thresholds untouched).
- `.env.example`: `ANTHROPIC_API_KEY` added (noted: web search must be enabled), `PERPLEXITY_API_KEY` and `OPENAI_MODEL` removed, `OPENAI_API_KEY` kept as embeddings-only.
- `grep -r "chat.completions" lib app` returns nothing.

## Decisions
- **Models in one place:** `CLAUDE_MODELS` in `lib/ai/config.ts`: `agent = claude-sonnet-5-5` (URL import, modify, discovery), `cheap = claude-haiku-5-5` (both normalisers). Per-function settings (model, max tokens) live in `AI_CONFIG`. Temperature settings were dropped (not needed; newer models may reject them).
- **`tool_choice` is `auto`, not forced.** The brief said "single forced tool". The real API rejected `tool_choice: {type: "tool"}` on `claude-sonnet-5-5` ("not supported for this model"), and `thinking: disabled` is also rejected for it. So `callForcedTool` offers one tool and appends "Respond only by calling the X tool" to the system prompt; it throws if no `tool_use` block comes back. With one tool this worked on every real run. The name `callForcedTool` is kept for the intent; if a later session needs hard guarantees, revisit when the model supports forcing.
- **Web search tool version:** `web_search_20250305` (widest support; the newer versions bring dynamic filtering we don't need), max 5 searches per request.
- **Discovery can't force its result tool** (forcing would stop it searching), so `discoverRecipes` uses auto, handles `pause_turn` continuations (up to 3), and nudges once if Claude answers in text. Logic lives in `lib/ai/discoverRecipes.ts`; the route is a thin wrapper.
- **Lazy client:** `getAnthropic()` creates the SDK client on first use, so importing never needs a key (builds, jsdom tests).
- **Schemas** for all tools are in `lib/ai/schemas.ts`.
- Prompts: only the "Return JSON ..." instructions were replaced with "submit with the tool"; no quality changes.
- Route returns `Anthropic API key not configured` (500) when `ANTHROPIC_API_KEY` is missing; other errors map to the existing generic message.

## How it works
**Old way:** ask the model for JSON in free text (`response_format: json_object` or "return ONLY JSON"), then `JSON.parse` the string, stripping markdown fences and regex-hunting for the first `{...}` when it misbehaved.

**New way:** define a tool whose `input_schema` is the shape we want, and tell Claude to call it. The reply contains a `tool_use` block whose `input` is already a parsed object that follows the schema (required fields, enums, nullable types). No parsing step, no fences.

```ts
// lib/ai/claude.ts (the heart of it)
const message = await getAnthropic().messages.create({
  model, max_tokens, system: `${system}\n\nRespond only by calling the ${toolName} tool.`,
  messages: [{ role: 'user', content: prompt }],
  tools: [{ name: toolName, description, input_schema: schema }],
  tool_choice: { type: 'auto' },
})
const block = message.content.find(b => b.type === 'tool_use' && b.name === toolName)
return block.input as T   // already an object
```

Each call site (`extractIngredientsFromURL`, `modifyMealPlan`, `normaliseMasterItems`, `llmNormalise`) now only builds its prompt, names its schema from `lib/ai/schemas.ts`, and maps the result.

**Discovery** (`lib/ai/discoverRecipes.ts`) gives Claude two tools: the Anthropic-hosted `web_search` (runs on Anthropic's servers; results come back inside the same response) and our `submit_recipes`. Claude searches, then calls `submit_recipes` with 3 recipes. If the server-side search loop pauses (`stop_reason: pause_turn`) we send the turn back to continue.

**Real runs** (local Postgres, dev key; all on 12 Oct 2026):
1. *Inspire Me*, prompt "quick midweek chicken dinners": 3 recipes with real URLs, e.g. "20-Minute Garlic Chicken Pasta with Butter" (`https://keytomylime.com/garlic-chicken-pasta-recipe/`, chicken / pasta / quick / new). Also exercised through the running app: `POST /api/recipes/discover` with "easy vegetarian pasta" returned 3 recipes in the `{recipes: [...]}` shape.
2. *URL import* of a pancake recipe page: name "Easy Fluffy Pancakes"; "1 1/2 cups all-purpose flour" became `190 g all-purpose flour`, "1 1/4 cups milk" became `300 ml`, "8 oz blueberries" became `225 g` (notes: optional); egg gets notes "beaten". Caveat: the sandbox egress policy blocked every external recipe site (403 on CONNECT), so this ran against the same kind of HTML served from a local fixture server, not a live site. The Claude call and parsing are the real path.
3. *Ingredient normalisation* (haiku): "Sainsbury's Garlic Granules 100g" -> `garlic granules` / `garlic (ground)`; "Warburtons Toastie Sliced White Bread 800g" -> `white bread`; "Sainsbury's Baby Plum Tomatoes 250g" -> `baby plum tomatoes`. Single ingredient "2 scallions, chopped" -> canonical `spring onion`, form null. (Quality note: "garlic granules" -> "garlic (ground)" differs from the prompt's own "garlic (dried)" example; prompt tuning is out of scope.)
4. *Meal-plan modify* ("fill the empty slots, keep Monday and Tuesday protein, prefer fish on Thursday"): all 28 slots filled, locked Monday/Tuesday proteins kept, no repeats, Thursday got "Salmon Pea Pasta", explanation text returned. The seed has only 11 recipes and no lunch/vegetable recipes, so the run added throwaway in-memory lunch/veg/carb recipes (not written to the DB).

## Handoff
- Use `callForcedTool` (`lib/ai/claude.ts`) for any one-shot structured output, `getAnthropic()` for anything else. Don't hardcode model names: use `CLAUDE_MODELS` / `AI_CONFIG`.
- `claude-sonnet-5-5` rejects forced `tool_choice` and `thinking: disabled` (it wants `between_tools`). S05's hand-rolled loop should use `tool_choice: auto`. `claude-haiku-5-5` accepted forcing.
- `USE_LLM` env var still gates the single-ingredient LLM fallback (`normaliseRecipeIngredient`); unchanged.
- `ingredientEmbeddings.test.ts` mocks `../ai/openaiEmbeddings`.
- The embeddings-failure log message in `syncPipeline.ts` still says "OpenAI API may be unavailable", which is still accurate (embeddings).
- Sandbox note for later sessions: external websites are blocked from build sessions; use local fixtures for URL-fetch tests.
- Rehaul-wide: `ANTHROPIC_API_KEY` must exist in Vercel (Preview and Production) before merging.
