# S04 — Recipe book UI

## Built
- The recipes page is now a book. A new "Type" filter (All / Full recipes / Quick) sits beside the existing filters. Quick items show as compact amber-edged cards; full recipes that have a method carry a small "Method · N steps" line; full recipes without one look as before.
- Each recipe name links to a new recipe page, `/recipes/[id]`: name, quick badge, description, servings, total time, ingredients (amount + unit when present, free text otherwise), method steps (ingredient tokens rendered as "500 g beef mince", timer shown), notes, source link. No method means no Method section at all, with no prompt.
- Editing is still the modal, now also reachable from the recipe page. The editor covers ingredients (add, remove, paste a list), steps (add, remove, up/down, optional timer, insert-ingredient), kind, servings, total time, description and notes, plus all the old fields and the "extract from URL" helper.
- A disabled "Cook" button on the recipe page is a marked placeholder for S08.

## Decisions
- **Modal vs page editing: kept as a modal** (orchestrator decision). The editor is a self-contained component, `components/recipe/RecipeEditor.tsx` (props: `recipe?`, `onSubmit`, `onCancel`, dish options). It owns all form state and touches nothing outside, so it can later be embedded in a page or a modal unchanged. Open question for Ronen: modal vs page editing.
- **Ingredient ids stay stable across edits.** The old PATCH deleted and re-created every ingredient, which would have orphaned `{ing:<id>}` tokens in steps. Now `lib/recipeWrite.ts` updates rows whose id is sent, creates new ones, and deletes only the ones left out. New rows get a client-made id (`n` + 20 chars, valid for the token alphabet), accepted on create.
- **Steps are validated on save** with S03's `validateStepText`; an unknown ingredient id gives a 400 and nothing is saved (transaction). Malformed fragments are left as plain text.
- **Steps are replaced wholesale** when `steps` is sent (contiguous 0-based order, blank steps dropped); when `steps` is omitted the method is untouched, so older callers cannot wipe it.
- **Removing an ingredient in the editor** turns its tokens in the steps into its plain name, so a step never dangles.
- **Editor shows `{name}` not `{ing:id}`.** Typing `{onion}` in a step becomes the token for the ingredient named onion (case-insensitive, first match for duplicates); unknown braces stay as text. A "Reads as: ..." preview shows the rendered sentence. Helpers in `lib/stepEditorText.ts`.
- **`parseAmount` runs on every ingredient save** (create and update), so `amount` is populated immediately instead of waiting for the next build backfill. `quantity` and `unit` are saved as typed.
- **Legacy `Recipe.ingredients` text** is kept in step: the editor sends the composed text, and the server composes it if absent.
- Timer is entered in minutes and stored as seconds. Servings and total time are whole numbers; invalid values give a 400.
- Quick filter is client-side like the others; `GET /api/recipes` also accepts `?kind=`. The list API now includes `steps`.
- Visual direction: kept the existing blue/fuchsia Tailwind look rather than introducing a new style; quick items use an amber accent.
- RecipeForm was renamed into the editor (git mv); `AIImportSection` is unchanged. I did not build import (S05).
- Env note: integration tests ran against `mealplanner_test_s04` (owned by `mp`) via `TEST_DATABASE_URL` etc.

## How it works
Components:
- `app/recipes/page.tsx` (server) -> `RecipesClient` (owns the list, filters, add/edit modal, Inspire modal; data via `useRecipes`) -> `RecipeFilters` + `RecipeCard`.
- `RecipeCard` draws one card: compact if `kind === 'quick'`, otherwise the full card with the method indicator. The name links to the page.
- `app/recipes/[id]/page.tsx` (server) reads the recipe with ingredients and steps straight from Prisma and lays out the page. `RecipeMethod` renders the steps. `RecipeActions` (client) holds the Cook placeholder and the Edit button, which opens `RecipeModal` and PATCHes, then `router.refresh()`.
- `RecipeModal` is only the overlay. `RecipeEditor` is the whole form and composes `IngredientsEditor` (rows) and `StepsEditor` (steps). Those two are presentational; the editor owns state.
- Saving goes through `lib/recipeWrite.ts` (`createRecipeFromForm`, `updateRecipeFromForm`), used by both API routes.

How a token becomes text: a step is stored as `Add {ing:abc} and stir`. On the recipe page `RecipeMethod` calls `parseStepText` (S03) to split it into text and ingredient segments, looks each id up in the recipe's ingredients and prints `describeIngredient(ing)` in bold ("500 g beef mince"); an unknown id prints "the ingredient". In the editor the same stored text is shown as `Add {beef mince} and stir` by `stepToEditorText` and converted back by `editorTextToStep`.

## Try on the preview
1. Recipes: use the new Type filter. "Quick" shows only compact cards; "Full recipes" hides them. Recipes with a method show "Method · N steps".
2. Tap a recipe name: the recipe page opens with ingredients. A recipe without a method shows no Method section.
3. Edit, then Add step three times. Type `{` plus an ingredient name in a step (or use "Insert ingredient"), set a timer on one, save: the page shows the steps with amounts in bold and "Timer: 10 min".
4. Edit a quick item (e.g. Simple Fries), choose "Quick", save: it becomes a compact card and shows under the Quick filter.
5. On the recipe page, the Cook button is greyed out (placeholder).
